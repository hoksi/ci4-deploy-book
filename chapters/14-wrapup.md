# 14장. 마무리

## 지금까지 만든 것

**1부 — 배포 전에 알아야 할 것**
- 호스팅 유형(공유 호스팅/VPS/클라우드) 분류와 각각의 근본적 차이
- `CI_ENVIRONMENT`에 따른 운영 설정, `.env` 운영값 체크리스트

**2부 — 제약된 공유 호스팅에 배포하기**
- SSH로 뭐가 되고 안 되는지 먼저 진단하는 절차
- git 작업 복사본 기반 배포, `--ff-only`, vendor 동기화
- SQLite(로컬 왕복) / MySQL(원격 접속 또는 phpMyAdmin) 마이그레이션 전략
- 캐시 레이어를 바깥에서 안으로 순서대로 배제하는 진단법

**3부 — VPS/클라우드로 확장하기**
- 멀티스테이지 Dockerfile, docker-compose로 로컬 재현
- GitHub Actions로 테스트 자동화 + 배포 자동화(SSH 패턴 / 이미지 빌드 패턴)
- Nginx 리버스 프록시, SSE 버퍼링 설정, Let's Encrypt HTTPS

**4부 — 운영 안정성 확보하기**
- 로그 임계값 조절 + Slack 알림 핸들러 + 헬스체크 엔드포인트
- File → Redis 캐시 전환, 캐시 적합도 판단 기준, 무효화 전략
- `composer audit`/Dependabot, 보안 헤더, 전역 Rate limiting
- DB/파일 백업 자동화, 오프사이트 백업, 복구 리허설

## 반복해서 나온 원칙들

- **안 되는 걸 억지로 되게 만들지 말고, 되는 걸 조합해서 우회한다** (2부 전체 — git/cp/tar는 되는데 php-cli만 안 될 때)
- **장애가 다른 장애로 번지지 않게 한다** (캐시 서버가 죽어도 dummy 핸들러로 통과, 알림 전송 실패가 요청 자체를 막지 않도록)
- **자동화된 것은 반드시 리허설해본다** (백업은 복구해봐야 진짜 백업, CI/CD는 실제로 실패시켜봐야 안전망 역할을 하는지 확인 가능)
- **설정값이 범인일 가능성을 항상 열어둔다** (6장 — 캐시처럼 보이는 문제의 상당수는 그냥 설정값 문제)

## 1권과의 관계

1권이 "무엇을 만드는가"였다면, 2권은 "만든 걸 어떻게 세상에 내놓고 지키는가"였습니다. 두 책을 한 문장으로 요약하면: **기능은 로컬에서 완성되지 않습니다. 배포되고, 운영되고, 장애를 겪고 복구되는 과정까지가 실제로 "서비스를 만드는 일"입니다.**

## 더 다뤄볼 수 있는 것들

- **멀티 서버/로드밸런서 환경으로 확장하기** — 이 책은 단일 서버를 전제로 했습니다. 트래픽이 더 늘어나면 세션 공유(Redis), 파일 업로드 공유 스토리지(S3 등) 같은 주제가 추가로 필요합니다.
- **Blue-Green 배포, 카나리 배포** — 8장의 배포는 "새 버전으로 그냥 교체"하는 방식입니다. 다운타임을 더 줄이려면 두 버전을 동시에 띄워두고 트래픽을 점진적으로 옮기는 전략을 고려할 수 있습니다.
- **인프라를 코드로 관리하기(IaC)** — Terraform 같은 도구로 서버 설정 자체를 코드화하면, 서버를 새로 만들 때마다 손으로 설정을 반복하지 않아도 됩니다.
